Where Northwind Bank went wrong
01

A generic formula

Implemented ÷ all test cases × 100. The number gets reported, then forgotten.

02

No target

Nobody agreed in advance what “good” looks like, so the number is never judged.

03

Assuming 1:1

One manual case can become many automated checks, or many fold into one. Counting scripts is not coverage.

04

Ignoring feasibility

Some tests can't be automated, by nature or by design. Left in the denominator, 100% is impossible.

How it's set up

Reading this report

  • Every test case carries a feasibility:* label — automatable or not — set once, by nature or design.
  • Automatable cases track automation:* — none → planned → in-progress → implemented.
  • Effective Coverage only ever divides by automatable cases — infeasible ones never deflate the number, and never let it hit 100% by accident either.
